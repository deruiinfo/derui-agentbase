# Agent Kit for Backend · 一页可执行方案

> **定位**：AI 原生的自托管后端基座 —— 人提需求，AI 用**标准工具**生成带三层权限与审计的业务系统。
> **品类**：Agent Kit for Backend（面向 AI agent 的后端工具套件）。
> **一句话卖点**：*你（或你的 AI）说业务需求，基座自动长出「表 + RLS 权限 + API + 后台页 + 测试」。*

## 1. 目标客户（买家是人）
| 客户 | 诉求 | 为什么买 |
|---|---|---|
| **半技术型创始人** | 用 AI 快速搭业务后台 | 比"AI + 真 Supabase"多了**私有化/数据主权** |
| **AI 实施/外包团队** | 快速交付客户系统 | 生成器+护栏 → 交付快、质量稳 |
| **懂点技术的老板** | 指示 AI 开发 | 基座"AI 友好"，AI 不跑偏 |

## 2. 要解决的核心问题
> 直接给 AI 一个脚手架，**AI 会绕过权限体系手写 SQL/路由** → RLS、字段级、审计全部失效。
> 所以产品不是"脚手架"，而是"**工具化的基座**"：AI 只能通过**受控工具**改库和生成代码。

## 3. Agent Kit = 5 件套
| 组件 | 内容 | 现状 |
|---|---|---|
| ① **Schema DSL** | `resource` 声明：字段 + 角色 + 行/列权限 | 部分（`schema.ts` 已是声明式） |
| ② **生成器 CLI** | `derui generate resource <name>` → 迁移+RLS+API+CRUD 页+测试 | **NEW（M3）** |
| ③ **MCP Server** | 把安全操作暴露为工具，供任意 AI 调用 | **NEW** |
| ④ **约定与护栏** | `AGENTS.md`/skill + 默认拒绝 + 工具为唯一入口 | **NEW** |
| ⑤ **自检闭环** | 生成后自动跑 `e2e`（权限矩阵）并迭代 | 已有 `e2e-docker.sh`，需工具化 |

## 4. 工作流
```
人：业务需求（自然语言）
   → AI agent：读 AGENTS.md + 调用 MCP 工具
      → schema.apply（声明资源）
      → resource.generate（生成实现）
      → db.migrate + test.run（自检）
      → 失败则读日志、修正、重跑
   → 交付：私有化后台（带权限与审计）
```

## 5. MCP 工具清单（契约）
| 工具 | 作用 | 护栏 |
|---|---|---|
| `schema.get` / `schema.apply` | 读取/应用资源声明 | 声明式；自动生成 RLS |
| `resource.generate` | 由资源生成 API+页面+测试 | 仅生成，不手写 SQL |
| `db.migrate` / `db.seed` / `db.reset` | 迁移/种子/重置 | reset 需二次确认 |
| `policy.preview` | 展示"角色×表×动作"权限矩阵 | 只读 |
| `test.run` | 跑 e2e/权限矩阵 | 只读 |
| `user.create` / `role.assign` | 建号/分配角色 | 需管理员上下文 |
| `deploy.up` | `docker compose up` | 需确认 |

> **硬护栏**：① 所有 DB 变更只能经工具；② 权限默认最小、默认拒绝；③ 写操作全部落审计；④ 破坏性操作需确认。

## 6. 差异化（相对"AI + 真 Supabase"）
1. **私有化/自托管**：数据不出厂（合规/内网/信创）。
2. **Agent 契约明确**：MCP + 约定 + 护栏，AI 产出更稳。
3. **三层权限内建**：RBAC + 字段级 + RLS + 审计（Supabase 需自己配 RLS）。
4. **国内可用**：镜像/离线/中文。

## 7. 里程碑
| 阶段 | 内容 | 验收 |
|---|---|---|
| **M3.1** | `derui generate resource`（确定性生成） | 一条命令产出可跑的资源 |
| **M3.2** | `AGENTS.md` + 机器可读约定 | AI 按约定生成不跑偏 |
| **M3.3** | MCP Server（工具契约 + 护栏） | AI 经工具改库 |
| **M3.4** | 自检闭环（生成→e2e→迭代） | AI 自愈到全绿 |
| **M3.5** | 用一个真实业务验证 | 正确率/耗时记录 |

## 8. 验证清单（立项/投入前）
1. 拿 DeepSeek/Claude Code 用**现有基座**真跑一个业务模块，量**正确率**与需要人介入的比例。
2. 目标客户是"半技术创始人"还是"非技术老板"？（决定是否要 AI 实施兜底）
3. 他们愿为"AI 可直接用的私有化基座"付多少？谁决策？
4. AI 是否真的"认识"这套约定（喂 `AGENTS.md` 后产出质量对比）。

## 9. 风险
| 风险 | 应对 |
|---|---|
| LLM 端到端不可靠（建 70–80%） | 把"全自动"降级为"AI 主导 + 人/AI 迭代"；保留实施服务 |
| 竞品（Lovable/Bolt/v0/Supabase MCP） | 差异=私有化 + 明确 Agent 契约 |
| 非技术老板兜不住失败 | 目标锁定半技术客户，或提供 AI 实施兜底 |
| 运维责任 | 托管 or 客户技术人；发行版内置运维 |

## 10. 定位句（对人 / 对 AI）
- **对人**："你提业务需求，AI 用标准工具生成带权限与审计的私有化后台系统。"
- **对 AI**："一套约定明确、可调用、被管住、能自检的后端基座。"
